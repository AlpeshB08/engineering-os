# Reuse Standards

## Rules

1. Search for existing components, hooks, utilities, modules, API clients, and patterns before creating new ones.
2. Document a reuse map in the Implementation Plan.
3. New shared abstractions require justification (duplication cost, missing capability, or approved architecture change).
4. Match naming, folder structure, and import aliases already used in the repo.
5. Prefer composition over parallel competing patterns.
6. Do not introduce a new state-management, styling, or testing library unless approved via architecture gate.
