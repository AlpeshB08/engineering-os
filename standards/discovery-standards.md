# Discovery Standards

## Rules

1. Inspect the repository before recommending structure or writing product code.
2. Cite file paths for every material finding.
3. Classify archetype as frontend, backend, fullstack, monorepo, or unknown — based on evidence only.
4. Record backend availability as `yes`, `no`, or `unknown`.
5. List unknowns explicitly; never fill gaps with guesses.
6. Refresh detection (`eos detect`) when the stack or layout may have changed.
7. Discovery notes must restate the request without expanding scope.
