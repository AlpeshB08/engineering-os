# Concepts

## Workflow

A named, ordered process (e.g. `feature-development`) defined in YAML. Starting a workflow creates a **run** with artifacts and state.

## Phase

A reusable stage of work (bootstrap, discover, plan, implement, …). Phases declare exit criteria, required artifacts, and optional gates.

## Artifact

A concrete document produced during a run (Feature Contract, Implementation Plan, Verification Plan, etc.). Artifacts are evidence; empty placeholders do not satisfy exit criteria.

## Gate

A human approval checkpoint recorded in state (`pending` | `approved` | `rejected`). Agents must not advance past a pending required gate.

### Standard gates

| Gate ID | Meaning |
|---------|---------|
| `contract-approval` | Scope and acceptance criteria agreed |
| `architecture-approval` | High-impact / architectural change approved |
| `delivery-signoff` | Ready for PR/release |

## Capability

A detected repository affordance (e.g. `jest`, `eslint`, `github-actions`, `backend-source`, `monorepo`). Capabilities gate which verification commands and checklists apply. Absence means “do not assume.”

## Repository Profile

Living summary of stack, layout, capabilities, reuse inventory, and backend availability (`yes` | `no` | `unknown`).

## Backend Dependency

Artifact describing required server contracts. When backend access is missing, it records gaps and mock/stub strategy instead of inventing APIs.

## Feature Contract

Scope agreement: problem, users, in/out of scope, acceptance criteria, non-goals, constraints.

## Implementation Plan

Sequenced change plan with reuse map, files to touch, risks, and approval triggers. Written before code.

## Verification Plan

Commands and manual checks to prove the change. Skips must cite missing capabilities.

## Decision Log

Append-only record of approved trade-offs and architecture decisions for the run (and optionally promoted to KB ADRs).

## Delivery Preparation

PR/release package: summary, test plan, rollback notes, open risks. Invalid unless verification evidence exists.

## Knowledge Base (KB)

Reusable engineering memory. Framework ships a baseline; consumers may overlay local KB content.

## Project DNA

Machine + human inventory of reusable assets and conventions produced by `eos intel scan`.

## Feature Impact

Artifact estimating modules/components/routes/APIs/stores/permissions/regression areas affected by a Feature Contract.

## Reuse Analysis

Ranked candidate list with reuse/adapt/create recommendation and rationale.

## Context Package

Slim, phase-specific prompt context generated by `eos context` / `eos next` to avoid full-repo dumps.

## Dependency Graphs

Import-heuristic graphs (shared components, API, routes, state) used for regression and change-impact analysis.
